OVERVIEW 
This project focuses on designing and implementing hardware acceleration for Token 
Generation of large language models (LLMs) using a RISC -based pipeline structure. 
The objective is to address the computational and memory challenges associated with 
traditional matrix multiplication (MatMul) operations in LLMs by leveraging 
lightweight MatMul-free architectures. 
The design integrates a 5-stage RISC pipeline (Fetch, Decode, Execute, Memory, Write 
Back) to optimize data flow and processing efficiency. Key features include the use of 
ternary quantization for lightweight operations, DDR3 FIFO for efficient data storage, 
and a control unit to manage read/write signals and hazard detection. TMATMUL 
(Ternary Matrix Multiplication) is incorporated into the memory stage, continuously 
retrieving data for efficient computation. 
The system was implemented on FPGA hardware to exploit its parallel processing 
capabilities, achieving significant improvements in memory usage, latency, and power 
consumption. The results demonstrate that MatMul -free architectures can provide 
efficient an d scalable solutions for LLM inference tasks, especially in resource -
constrained environments. 
This research highlights the potential of RISC -based hardware pipelines to enable 
lightweight, sustainable AI applications and sets the stage for further developments in 
efficient language modeling systems.

1.  INTRODUCTION 
1.1  Motivation 
The rapid evolution of large language models (LLMs) has transformed the 
landscape of artificial intelligence, enabling breakthroughs in tasks such as text 
generation, translation, summarization, and question answering. Models such as GPT -
4, PaLM, and LLaMA  have set new benchmarks in performance and versatility. 
However, these advancements come with significant computational and infrastructural 
costs. The training and deployment of such models demand massive memory 
bandwidth, specialized hardware, and enormous energy consumption. 
 For instance, OpenAI's CEO, Sam Altman [1], indicated at an MIT event in July 
that the cost of training GPT -4 exceeded $100 million. With inference latency and 
power consumption remaining critical bottlenecks for real -time applications. These 
challenges intensify as model sizes scale beyond 100 billion parameters, necessitating 
the development of more efficient model architectures and hardware accelerators. 
One of the main contributors to computational inefficiency in LLMs is matrix 
multiplication (MatMul), which dominates both dense layers and attention mechanisms. 
Despite their effectiveness, MatMul operations impose high silicon area, memory 
bandwidth, and energy demands , particularly on edge devices or custom hardware 
platforms such as FPGAs. 
This thesis proposes a MatMul -free approach for LLM token generation, 
supported by an FPGA -based RISC-style coprocessor, to address these inefficiencies 
and enable scalable, sustainable language modeling.

1.2 Background  
In recent years, the field of natural language processing (NLP) has been 
revolutionized by the advent of large language models (LLMs). These models, built 
upon the transformer architecture introduced by Vaswani et al. in 2017  [2], have 
demonstrated remarkable proficiency in a wide range of tasks such as machine 
translation, summarization, sentiment analysis, and question answering. Central to the 
success of LLMs is their reliance on high -dimensional vector operations, particularly  
dense matrix multiplications (MatMul), which are ubiquitous across all layers , from 
embeddings and attention to feedforward networks. 
Traditionally, LLMs rely heavily on linear transformations such as:

Where X is the input matrix, W the weight matrix, and b  the bias vector. These 
operations are implemented as dense matrix multiplications, often utilizing high -
precision floating-point formats (e.g., FP32 or BF16) 
However, the very computational operations that enable LLMs to functio n, 
specifically MatMul, also constitute a major barrier to their scalability and deployment. 
In modern transformer-based LLMs, matrix multiplications account for the majority of 
the computational workload and energy consumption. For instance, in each attention 
layer, the computation of attention scores through the dot-product of the query and key 
matrices involves expensive matrix-matrix multiplications (MMM), while feedforward 
layers typ ically rely on matrix -vector multiplications (MV). These operations are 
inherently resource -intensive, especially when implemented at scale with billions of 
parameters. 
To address this challenge, several strategies have emerged to improve the 
efficiency of neural network computations. One popular technique is quantization, 
which reduces the precision of weights and activations from 32 -bit floating -point to 
lower-bit representations such as 8 -bit integers (INT8), 4 -bit formats, or even binary 
and ternary levels  [3]. Quantization significantly reduces memory footprint and 
computational cost, making it attractive for hardware -constrained environments like 
mobile devices and embedded systems.  
Among these efforts, ternary quantization has gained attention due to its 
simplicity and hardware-friendliness. In this approach, weight values are restricted to a 
ternary set {−1,0,+1} , allowing multiplications to be replaced by additions, 
subtractions, or no operation at all. This simplification transforms matrix 
multiplications into ternary accumulations, which are substantially more efficient to 
implement on digital logic circuits. Whi le this drastically reduces arithmetic 
complexity, it introduces challenges in maintaining model expressiveness and training 
stability, issues that are typically addressed through advanced training strategies such 
as quantization-aware training and normalization layers like RMSNorm. 
Parallel to quantization, researchers have explored alternative neural 
architectures that aim to eliminate MatMul operations entirely. These MatMul -free

architectures utilize components like linearized recurrent units (e.g., MLGRU) and 
Gated Linear Units (GLUs) that depend on element -wise operations and simplified

At the hardware level, MatMul operations also impose a bottleneck. While GPUs 
and TPUs are designed with matrix multiplications in mind, leveraging parallelism and 
dedicated tensor cores , they still suffer from high power consumption and memory 
bandwidth limitations. Moreover, these platforms are not always suitable for edge 
deployment due to size, cost, and thermal constraints. In contrast, FPGAs offer a 
flexible, reconfigurable alternative capable of implementing custom datapaths tailored 
to specific comp utational needs. By exploiting this flexibility, it is possible to design 
efficient hardware accelerators that omit MatMul operations and instead rely on 
lightweight operations like ternary accumulation. 
In this context, the integration of MatMul -free models with FPGA -based 
architectures presents a promising direction for efficient language model inference. By 
marrying algorithmic innovation with hardware specialization, it becomes possible to 
achieve both high throughput and low energy consumption, enabling real -time LLM 
applications in environments where traditional solutions fall short. 
 "Scalable MatMul-free Language Modeling" has implemented token generation 
using an FPGA to reduce the processing load on the GPU. This FPGA -based approach 
efficiently fetches essential matrix data, including weights, input values, biases, and 
other relevant parameters, directly from RAM. This offloads significant computational 
overhead from the GPU, enabling more efficient utilization of resources.  
 Furthermore, the FPGA design includes dedicated custom instructions tailored 
for fundamental matrix operations such as addition, subtraction, division, and 
multiplication. Leveraging these capabilities, it seamlessly handles advanced 
computational tasks critical for machine learning operations, including the calculation 
of Gated Recurrent Units (GRUs), the exponential softmax activation function, and the 
sigmoid activation function.

1.3 Research Gap 
Despite the growing interest in model compression and low-precision inference, 
fully MatMul-free architectures for large language models (LLMs) remain 
underexplored, especially in the context of hardware -level implementation. While 
significant progress has been made in reducing the computational complexity of dense 
neural networks, a critical review reveals three major gaps that this thesis aims to 
address. 
1.4.1 Limited Hardware Deployment of MatMul-Free Models 
Many recent works, such as BitNet and Scalable MatMul -Free Language 
Modeling, have demonstrated that ternary and binary quantization can retain 
competitive accuracy with reduced compute. However, these models are primarily 
evaluated in GPU-based environments, which are still optimized for traditional matrix 
multiplications. Even though some attempts have been made to simulate ternary models 
in software or use low -bit kernels (e.g., BitBLAS, FlashAttention), real hardware 
acceleration using FPGAs or ASICs is seldom explored. 
Existing implementations often stop at kernel -level optimization or software 
simulation. There is a lack of end-to-end RTL designs that implement token generation 
using fully MatMul-free logic with quantized dataflow. 
1.4.2 Lack of Modular, Scalable Pipelines for Ternary Logic 
Most existing FPGA LLM accelerators focus on optimizing full -precision or 
fixed-point MatMul operations (e.g., systolic arrays, tile -based GEMM). These 
architectures are not easily adaptable to ternary arithmetic, which relies heavily on 
element-wise addit ions and conditional negations instead of dense matrix 
multiplication.

Moreover, there is little literature on pipeline -structured, RISC -style 
architectures tailored specifically for language models using ternary logic. The absence 
of custom instruction sets and dedicated modules (e.g., TMATMUL blocks, RMS 
normalization, acti vation logic) for ternary computation limits the ability to deploy 
lightweight models on FPGAs or embedded systems. 
There is no standardized pipeline architecture designed to handle ternary vector 
operations, memory-mapped vector I/O, and instruction -level control under a unified 
datapath. 
1.4.3 Insufficient Benchmarking on Real Token Generation Workloads 
Most prior benchmarks evaluate compressed models on traditional datasets (e.g., 
GLUE, SuperGLUE, or causal loss curves). These results, while useful for validating 
performance at a macro level, do not capture the token -by-token generation dynamics 
critical in LLM inference. 
Furthermore, latency, throughput, and power measurements are often derived 
from simulation or kernel-level profiling. There is minimal research that: 
+ Profiles the actual token throughput per second under hardware constraints 
+ Breaks down the latency contribution per hardware stage 
+ Analyzes the energy efficiency at inference scale for quantized token generation 
A practical system that completes forward-pass token generation in a pipelined, 
hardware-accelerated fashion has not been fully demonstrated or benchmarked against 
GPU inference.

1.4 Research Objective 
The primary objective of this research is to design, implement, and evaluate a 
MatMul-free coprocessor architecture tailored for token generation in large language 
models (LLMs). The project targets hardware -level acceleration on FPGA platforms, 
aiming to improve inference speed, memory efficiency, and energy consumption in 
resource-constrained environments. 
1.4.1. Core Goals 
The research is guided by the following core goals: 
Eliminate Matrix Multiplication Overhead 
Traditional transformer models rely heavily on high -precision matrix 
multiplication (MatMul) for dense and attention layers. These operations are 
computationally intensive and memory -bound. This work seeks to replace all MatMul 
operations with ternary accumulations, leveraging ternary weight matrices ({-1, 0, +1}) 
and addition-only computation pipelines. 
Design a Custom 5-Stage RISC-style Pipeline 
The proposed system mimics the classic RISC -V pipeline architecture (Fetch, 
Decode, Execute, Memory, Write Back), customized to support vectorized instructions 
and matrix operations. The instruction set includes arithmetic operations (ADD, SUB,

DIV, EXP), memory commands (LDV, STV), and custom TMATMUL (Ternary 
Matrix Multiplication) instructions. 
Optimize Memory Bandwidth and Access Patterns 
External DRAM access often becomes a bottleneck in FPGA designs. This 
project integrates a custom dual -port memory controller and burst -aligned memory 
mapping scheme to manage concurrent reads/writes efficiently  for matrix 
multiplication. The goal is to support real-time matrix operations with minimal stalling 
or backpressure. 
Achieve High Performance on FPGA 
The architecture is synthesized and implemented on a Xilinx Kintex -7 FPGA. 
Performance metrics including logic utilization, BRAM usage, clock frequency, 
latency, throughput, and power consumption are carefully measured. A critical 
objective is to demonstra te significant energy and memory efficiency gains over 
MatMul-based implementations, while sustaining reasonable throughput (tokens/sec).

model operations? 
+ What are the trade -offs in latency, power, and area when replacing MatMul with 
ternary accumulation in large-scale vectorized inference? 
+ How scalable is the architecture across different model sizes (e.g., 370M, 1.3B 
parameters) and sequence lengths?

2. RELATED WORKS 
The design of hardware -efficient large language models (LLMs), particularly 
those eliminating traditional matrix multiplication (MatMul), has gained significant 
attention due to the growing demand for computationally efficient and scalable 
architectures. This section reviews prior efforts across three major themes: MatMul-free 
architectures [4], quantization and low -precision computing  [3], and FPGA -based 
language model acceleration. 
2.1  Scalable MatMul-free Language Modeling 
Matrix multiplication (MatMul) has long been a central operation in deep 
learning, serving as the foundation of dense layers, attention mechanisms, and 
convolutional operations. However, MatMul is also one of the most resource -intensive 
components in neura l networks, especially in large -scale language models (LLMs) 
where embedding sizes and layer depths are substantial. The cost of MatMul manifests 
in high memory bandwidth requirements, significant energy consumption, and 
hardware inefficiencies —particularly for edge deployment or FPGA -based 
implementation. As a result, recent research has explored alternative architectures that 
eliminate or reduce reliance on MatMul while retaining strong performance. These 
approaches are collectively referred to as MatMul-free architectures. 
One of the most influential contributions to this field is the Scalable MatMul-
free Language Modeling  framework by Zhu et al  [4]. This work introduces the first 
LLM architecture that eliminates MatMul operations entirely while maintaining 
competitive accuracy at the billion-parameter scale. Their architecture achieves this by 
systematically replacing all multiplications with ternary accumulati ons, element-wise 
operations, and simple arithmetic logic, implemented across both token and channel 
mixers. 
Ternary Dense Layers (BitLinear Layers) 
The cornerstone of MatMul -free architectures is the BitLinear layer , which 
replaces the standard matrix multiplication in dense layers with ternary accumulation. 
In this formulation, the weight matrix is quantized to contain only three values: {−1, 0,

+1}. This dramatically reduces computational complexity by eliminating 
multiplications altogether, since any input value can be added, subtracted, or ignored.

2.2 Quantization and Low-Precision Language Models 
The growing size and complexity of large language models (LLMs) have spurred 
interest in quantization techniques that reduce computational overhead and memory 
footprint. Quantization converts high -precision weights and activations (typically 
float32 or bfloat16) into lower-precision representations such as 8-bit integers, ternary 
values {−1, 0, +1}, or even binary values {−1, +1}. These techniques not only reduce 
model size but also enable efficient execution on custom hardware such as FPGAs and 
ASICs. 
2.2.1 Full-Precision vs. Quantized Models 
Traditional LLMs like GPT-3 and LLaMA utilize high-precision operations that 
consume significant power and memory, especially during inference on edge or 
embedded devices. As a result, quantization has emerged as a key enabler for deploying 
these models in  resource-constrained environments. Quantization reduces arithmetic 
complexity and allows for faster computation through bitwise operations and smaller 
data movement. 
For instance, an unquantized matrix multiplication involves thousands of float32 
multiply-accumulate (MAC) operations, which are not only energy -hungry but also 
require wide memory buses. In contrast, a quantized multiplication using ternary 
weights avoids  multipliers entirely, reducing the operation to simple additions, 
subtractions, or skips. 
2.2.2 Ternary Quantization 
Ternary Quantization is a compromise between binary quantization and full -
precision weights. It restricts weights to one of three values: −1, 0, or +1. This ternary 
constraint eliminates multipliers and significantly reduces memory access cost.

3.1 Token generation 
Tokenization is the process of converting raw text into smaller units called 
tokens. These tokens can be words, subwords, or even individual characters, depending 
on the tokenizer's design. For instance, the sentence "The cat sat on the mat." might be 
tokenized into ["The", "Ġcat", "Ġsat", "Ġon", "Ġthe", "Ġmat", "."] 1  (example from 
BPE or SentencePiece). 
Each token is then assigned a unique integer ID based on the tokenizer’s 
vocabulary: 
"The"   →  132 
"Ġcat"  →  4567 
"Ġsat"  →  2231 
"Ġon"   →  1021 
"Ġthe"  →  132 
"Ġmat"  →  5844 
"."     →  4 
So the sentence becomes: [132, 4567, 2231, 1021, 132, 5844, 4] 
Once text is tokenized, each token is converted into a vector representation 
known as an embedding. Embeddings are dense numerical vectors that capture the 
semantic and syntactic properties of tokens. In these high -dimensional spaces, tokens 
with similar meanings are positioned closer together, allowing the model to understand 
relationships between words. 
These embeddings are generated through training on large corpora, enabling the 
model to learn contextual nuances and associations between words. For example, the 
words " The" and "cat" would have embeddings that reflect their related meanings, 
differing in specific dimensions that capture gender or role distinctions. 
These token IDs are then mapped into embedding vectors using an embedding 
matrix, which is a learnable parameter of the model.

3.2 The Cost of Matrix Multiplication 
Matrix multiplication (MatMul) forms the computational backbone of nearly all 
large-scale neural network architectures, including transformers used in large language 
models (LLMs). Despite its widespread adoption, MatMul is also the single most 
resource-intensive operation, posing serious challenges in terms of energy 
consumption, hardware efficiency, and latency, particularly for edge deployment or 
real-time inference.

3.2.2 Hardware Implications 
From a hardware design perspective, matrix multiplication demands: 
+ Multiply-Accumulate Units (MACs): Each consisting of a multiplier followed 
by an adder, these are expensive in silicon area and power. 
+ High-precision data paths: Floating -point (FP16, FP32) or fixed -point 
multipliers dominate logic utilization on FPGAs and ASICs. 
+ Large memory bandwidth: All operands must be fetched from memory, which 
increases latency and energy per operation. 
On FPGA platforms, multipliers consume DSP slices or ALMs (Adaptive Logic 
Modules), which are limited in number. Even with parallelization, maintaining high 
throughput across many MACs often requires: 
+ Clock frequency throttling (to reduce thermal load), 
+ Complex scheduling of memory access, 
+ And pipeline depth optimization to hide latency.

Moreover, GPUs and CPUs optimized for MatMul (e.g., via cuBLAS, oneDNN) 
depend heavily on cache locality, and their performance drops significantly when 
memory access becomes non-contiguous—common in high-dimensional LLMs. 
3.2.3 Energy and Latency Overhead 
In modern hardware: 
+ A 16 -bit floating -point multiplication can consume 3 –5× more energy than a 
simple addition or bitwise operation. 
+ Each MatMul operation incurs dynamic energy costs for both computation and 
DRAM access. 
Experimental studies show that over 90% of energy used during inference of 
LLMs goes to MatMul operations in attention and feedforward layers. Latency per 
token can range from 10 ms to 40 ms, depending on model size and sequence length, 
with MatMul dominating the critical path. 
This becomes particularly problematic for edge -AI deployments, where energy 
budgets are limited, and real -time latency is essential. The need to process billions of 
parameters under such constraints necessitates alternative computation strategies. 
3.2.4 Scalability Challenges 
As language models scale up from hundreds of millions to hundreds of billions 
of parameters (e.g., GPT-3: 175B), the proportion of resources spent on MatMul grows 
superlinearly: 
+ Quadratic growth in attention MatMuls with respect to sequence length L. 
+ Linear scaling in dense layer MatMuls with respect to model width ddd and depth 
N.

4.4  TMATMUL Block 
4.4.1 Motivation and Design Goals 
The TMATMUL (Ternary Matrix Multiplication) block is a cornerstone 
component in the MatMul -free coprocessor architecture, enabling efficient matrix -
vector multiplication using ternary quantization. Unlike conventional matrix 
multiplication, which requires multipliers and large amounts of memory bandwidth, 
ternary operations can be implemented using simple adders, subtractors, and conditional

logic, drastically reducing hardware complexity, power consumption, and memory 
overhead. This design is particularly advantageous for FPGA platforms, where 
multiplier resources are often limited and power efficiency is critical. 
The goal of the updated TMATMUL block is to significantly enhance 
parallelism, scalability, and data throughput. This is achieved by refining both the 
accumulation mechanism and the internal dataflow, ensuring that the design can handle 
large-scale language model workloads with high efficiency. 
4.4.2 Block Architecture and Dataflow 
The TMATMUL block has been re -engineered to support a fully pipelined, 
hierarchical accumulation structure tailored to the FPGA’s parallelism. The updated 
design includes: 
+ Input Decomposition: The ternary matrix is stored as a 2-bit representation for 
each element in an array format (tmatrix_data), while the input activation vector 
is stored in a separate array (matrix_in_data). This structure allows efficient 
memory access and direct indexing during multiplication. 
+ Element-wise Multiplication : Each element of the ternary matrix 
(tmatrix_data) is evaluated against its corresponding input vector element 
(matrix_in_data). The multiplication operation is simplified: 
o +1: Direct addition of the input element. 
o -1: Subtraction of the input element. 
o 0: Skipping the operation (no addition or subtraction). 
+ Row-wise Accumulation: Instead of performing a flat summation, the design 
implements an 8-stage pairwise accumulation pipeline: 
o Stage 0: 256 pairwise additions reduce 512 partial results. 
o Stage 1: 128 pairwise additions reduce 256 results. 
o Stages 2 to 7: Successive pairwise accumulations halve the results at each 
stage until a single final sum is obtained.

+ Final Output : The final accumulated result of each row is stored in a result

The ALU operates on a pair of 512-element vectors A and B, where each element

exponential arithmetic and instead fetch outputs in O(1) time per element, significantly

4.7 Hazard Detection and Pipeline Control 
4.7.1 Motivation and Overview 
In pipelined architectures, overlapping the execution of multiple instructions is 
essential to achieving high throughput. However, such overlap can introduce conflicts 
known as pipeline hazards , which must be carefully managed to avoid incorrect 
computation. In the proposed MatMul-free coprocessor, hazard detection plays a critical 
role in maintaining data correctness and enabling seamless instruction execution across 
the 5-stage pipeline (Fetch, Decode, Execute, Memory, Write Back). 
Hazards in this design are primarily induced by: 
+ Data dependencies across registers and memory 
+ TMATMUL operations, which are long-latency and stall-dependent 
+ FIFO occupancy conditions, such as full/empty buffer states 

=== PDF PAGE 61 ===
Graduation thesis                                                                     Instructor: PhD. Trần Hoàng Linh 
50 
 
+ Instruction conflicts where source data is not yet written back 
To handle these conditions, a dedicated hardware module (hazard_detect) 
generates control signals to stall or flush specific pipeline stages. These signals ensure 
that the system only advances instructions when all prerequisites are met. 
4.7.2 Types of Hazards in the Coprocessor 
The architecture identifies and handles the following four types of hazards: 
Memory Hazard (hazard_0) 
Triggered when a TMATMUL instruction is in the pipeline and the preceding 
stage has not completed a dependent memory operation (LDV, STV, or TMATMUL). 
This ensures data is available before reuse. 
FIFO Dependency Hazard (hazard_1) 
Arises when a memory or register read/write is attempted while the associated 
FIFO is near full or empty, potentially leading to an invalid transaction. almost_full and 
almost_empty flags are used to predict and prevent such cases. 
Write-Completion Hazard (hazard_2) 
Ensures that a write transaction to memory has finished before the next 
instruction overwrites or depends on its result. It checks for the absence of the 
write_finish signal. 
Instruction Validity Hazard (hazard_3) 
Detects invalid or undefined instructions in the fetch stage and prevents them 
from propagating down the pipeline by stalling the Program Counter (PC). 
4.7.3 Hazard Resolution and Control Signal Generation 
The hazard_detect module evaluates these conditions in parallel and encodes the 
results into a vector of stall signals: 
+ fd_stall: Freeze the fetch-decode register. 
+ de_stall: Halt decode-execute transition to await input readiness. 
+ em_stall: Block the execute-memory stage. 

=== PDF PAGE 62 ===
Graduation thesis                                                                     Instructor: PhD. Trần Hoàng Linh 
51 
 
+ mw_stall: Stop memory-writeback stage to avoid premature writes. 
+ pc_stall: Suspend PC increment, halting instruction flow. 
+ flush_wb: Explicitly clears the write -back stage if a TMATMUL overwrite 
condition is detected. 
These signals are computed using combinational logic based on instruction 
opcodes (instr_fd, instr_de, instr_em, instr_mw) and system flags (read_finish, 
write_finish, empty, full, etc.). 
4.7.4 Integration with Pipeline Registers 
Each pipeline stage includes an enable signal driven by the hazard detection 
logic. When a stall is asserted, the associated stage register freezes its state and prevents 
new instruction or data updates. This isolation allows upstream stages to continue 
processing, where possible, and prevents overwriting operands mid-computation. 
Additionally, the flush_wb signal enables an asynchronous reset of the Write 
Back stage. This is particularly important for cases where TMATMUL output must be 
invalidated due to incorrect or incomplete input vectors being loaded into memory. 
4.7.5 Design Tradeoffs 
The hazard control mechanism is designed for modularity and non -
intrusiveness: 
+ Hazard detection logic is encapsulated in a separate module with minimal 
dependencies. 
+ All stall signals are computed combinationally to prevent additional latency. 
+ The control logic avoids full pipeline flush unless absolutely necessary. 
This design choice balances pipeline utilization efficiency  with data 
consistency, ensuring robust operation even in complex sequences of vector 
instructions involving memory and register reuse.

Explanation of the Testcase 
Parallel Loading of Input and Bias Vectors:  The first three instructions 
(LOAD R0, V0, LOAD R2, V1, and LOAD R5, V2) simultaneously load input vectors 
and the bias term from memory into dedicated registers. This approach overlaps the 
memory access phase for multiple vectors, reducing stall cycles and pipeline bubbles. 
Normalization of Inputs: NORM R1, R0 performs RMS normalization on the 
first input vector. This step ensures that the input is scale-invariant, which is critical for 
stable quantization and ternary accumulation in downstream operations. 
Efficient Data Movement: STORE V0, R1 stores the normalized vector back 
into the memory-mapped vector file, ready for the subsequent TMATMUL operation. 
By reusing the same vector space, this reduces the need for additional LDV instructions.

is a key operation replacing traditional MatMul and implemented with ternary

Overlapping Normalization and Next TMATMUL: While the first 
TMATMUL is being prepared, the pipeline concurrently normalizes the next input

operands, maintaining a steady flow of operations without idle pipeline stages.

6. CONCLUSION AND FUTURE DIRECTIONS 
6.1 Conclusion 
This thesis presents a comprehensive exploration and hardware implementation 
of a scalable MatMul-free coprocessor architecture for accelerating token generation in 
large language models (LLMs). By eliminating traditional matrix multiplication 
operations, the proposed design sig nificantly reduces computational complexity and 
resource consumption, offering a lightweight alternative suitable for deployment in 
resource-constrained environments. 
The core of this work is a custom RISC-based 5-stage pipeline processor tailored 
for ternary arithmetic operations. At the heart of the architecture lies the TMATMUL 
(Ternary Matrix Multiplication) unit, designed to execute high -throughput, memory -
efficient inference operations using ternary quantized weights. Coupled with a robust 
control unit, hazard detection mechanisms, and SRAM FIFO -based register files, the 
system demonstrates low-latency execution and high parallelism. Implementation on a 
Kintex-7 FP GA platform validates the architecture's efficacy, achieving a token 
generation throughput of up to 87.42% faster than normal matrix multiplication with a 
power consumption profile on par with brain-level efficiency, particularly when scaled 
with multicore integration. 
Key achievements of this work include: 
+ A full RTL implementation of a MatMul -free coprocessor pipeline, integrating 
specialized instructions and vector operations aligned with the needs of LLM 
token generation. 
+ Realization of a custom ISA supporting row-wise arithmetic, normalization, and 
ternary operations. 
+ Integration of a burst -optimized DDR3 interface and a dual -FIFO memory 
architecture for streaming matrix operands and results. 
+ Empirical performance validation demonstrating significant reductions in 
latency, power, and memory footprint compared to traditional GPU -based 
inference engines.

This work challenges the prevailing reliance on matrix multiplication in LLMs 
and demonstrates that ternary quantized, MatMul -free architectures can deliver state -
of-the-art performance with drastically improved hardware efficiency. 
6.2 Future Directions 
Building on the foundational contributions of this thesis, several promising 
directions for future research and development are proposed: 
6.2.1. Performance Optimization and Resource Scaling 
+ Caching Strategies: Incorporate on-chip caching mechanisms for frequently used 
matrices and vectors to alleviate DDR memory bottlenecks. 
+ Instruction Fusion: Design compound instructions that combine multiple 
operations (e.g., TMATMUL + NORM) to reduce pipeline stalls and improve 
throughput. 
+ Multi-core Parallelism: Explore deployment of multi -core configurations with 
inter-core vector buses or NoCs (Networks-on-Chip) to enable concurrent token 
generation. 
6.2.2. Extending Model Capacity and Flexibility 
+ Dynamic Matrix Scaling: Extend support for variable matrix dimensions (e.g., 
256, 1024) through parameterizable datapaths and segmented memory mapping. 
+ Model Generalization: Validate the architecture on larger models (10B+ 
parameters) and diverse token types beyond 1×512 vectors. 
+ Support for Layer Fusion: Integrate layer fusion for token mixing and channel 
mixing stages to further reduce inter-layer memory transactions. 
6.2.3. Hardware-Software Co-design 
+ Compiler and Assembler Toolchain: Develop a domain-specific language (DSL) 
and assembler to map LLM layers directly into executable instruction sequences. 
+ Software Simulator: Create a high -level simulation environment for cycle -
accurate performance estimation and rapid prototyping before RTL deployment.

6.2.4. Application Deployment 
+ Edge AI and Low -power Inference: Target real -world applications such as 
conversational agents on embedded platforms (e.g., Raspberry Pi with FPGA 
overlay). 
+ Integration with LLM APIs: Enable seamless interaction between FPGA 
inference and front -end frameworks like ONNX Runtime or HuggingFace 
Transformers via lightweight RPC or PCIe interfaces. 
6.2.5. Comparative Benchmarking and Standardization 
+ Cross-platform Benchmarking: Systematically compare the coprocessor's 
performance with state -of-the-art LLM accelerators (NVIDIA H100, Google 
TPU, Cerebras CS-2). 
+ Open-source Ecosystem: Release RTL, instruction sets, and testbenches as open-
source assets to foster reproducibility and academic collaboration. 
6.3 Closing Remark 
The proposed architecture underscores a fundamental shift in how large -scale 
language models can be efficiently executed using lightweight, quantization -aware 
computation paradigms. As LLMs continue to permeate real-time, interactive systems, 
there is a growing imperative to decouple performance from energy consumption. The 
work presented herein lays a robust foundation for future innovations in green AI, 
enabling scalable, interpretable, and democratized access to large language models 
through energy-aware hardware-software codesign.
